# Скаляр атрибутом вершин, цвет — выборкой из текстуры палитры в шейдере

Поле температур подаётся на GPU как `float`-атрибут `aScalar` (одно число на вершину), а цвет вычисляется во фрагментном шейдере: значение → нормировка по диапазону → выборка из одномерной текстуры палитры. Смена шага времени перезаливает один Float32-буфер, а смена палитры, диапазона, изотерм и затенения — только uniform, геометрия не трогается. Главное — по треугольнику интерполируется **значение**, а не цвет: цвет между вершинами соответствует реальной промежуточной температуре, а изотермы проходят точно.

## Considered Options

- **Цвет в вершинах (`vertexColors`), считать на CPU.** Привычный путь в three. Но любая смена палитры или диапазона — пересчёт и перезаливка RGB всех вершин. И главное: GPU интерполирует **цвет**, а смесь синего и жёлтого в RGB — это не цвет промежуточной температуры (для радуги — вообще другой цвет). Изотермы по цвету не построить.
- **Значение в текстуре данных, выборка по UV.** Нужна UV-развёртка детали, а у STL её нет.

## Consequences

- Собственный `ShaderMaterial`: освещение, отсечение (шаг 8) и прочее пишутся в шейдере сами, встроенные чанки three не используются.
- Значение в точке клика считается той же барицентрической интерполяцией, что делает GPU, — число в панели совпадает с цветом.
