# Рендер по требованию вместо непрерывного цикла

Кадр рисуется только после `viewer.requestRender()`. В покое `requestAnimationFrame` не запланирован вообще, а несколько запросов за один кадр склеиваются в одну отрисовку. Инженерный вьюер большую часть времени статичен, и непрерывный цикл на 60 Гц жжёт GPU и батарею впустую.

## Considered Options

- **Непрерывный `requestAnimationFrame` + флаг `needsRender`** (вариант из START.md): не рисует лишнего, но браузер всё равно будит цикл 60 раз в секунду. Отвергнут: зачем просыпаться, если можно не засыпать.
- **Запланировать `requestAnimationFrame` в момент запроса** — выбран: в покое ноль работы.

## Consequences

- **Каждый, кто меняет сцену, обязан вызвать `requestRender()`.** Забыл — изменение не появится до следующего события. Это главная цена решения.
- Анимации, у которых нет внешнего события (инерция орбиты на шаге 4, проигрывание времени на шаге 9), должны сами запрашивать следующий кадр, пока не закончатся.
