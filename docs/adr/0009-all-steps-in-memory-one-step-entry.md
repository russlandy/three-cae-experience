# Все шаги поля в памяти; одна точка смены шага для всех представлений

Поле хранится целиком: массив `Float32Array` на каждый шаг времени (сейчас ≈ 3 МБ). Смена шага — копия нужного шага в буфер атрибута, термический цикл — проход по всем шагам в одной точке. Все представления, зависящие от шага (сцена, ползунок, 2D-сечение, график, значение в панели выбора), обновляются из одной функции `goToStep`, кто бы шаг ни менял: ползунок, клик по графику или проигрывание.

## Considered Options

- **Потоковая подгрузка шагов.** Обязательна для настоящих расчётов (миллион узлов × тысяча шагов ≈ 4 ГБ на величину), но для синтетического поля — лишняя сложность: кеш, отмена запросов, состояние «шаг ещё грузится» во всех представлениях.
- **Каждый источник смены шага обновляет представления сам.** Так было на шаге 7, и T в панели выбора «застывала». С тремя источниками и пятью представлениями это 15 связей, которые легко забыть.

## Consequences

- Переход на потоковые данные затронет `FieldView.setStep` (асинхронность) и построение цикла: у сцены доступ «все узлы, один шаг», у графика — «один узел, все шаги». Для второго нужен отдельный запрос или транспонированное хранение.
- Новое представление шага добавляется одной строкой в `goToStep`.
