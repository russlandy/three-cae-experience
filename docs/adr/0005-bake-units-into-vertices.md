# Конвертация единиц и осей запекается в вершины

Загрузчик (`toWorldMm`) умножает вершины на матрицу «единицы → мм, Z-вверх → Y-вверх, трансформация узла glTF» и выдаёт плоскую группу мешей с единичными трансформациями. Альтернатива — повесить `scale`/`rotation` на корневой узел — дешевле, но тогда координаты в буферах остались бы в единицах файла. Всё, что дальше работает с вершинами напрямую (поле температур по вершинам на шаге 7, зонд по ближайшей вершине на шаге 9, барицентрия picking на шаге 6), должно было бы помнить про эту матрицу. Запекание делает правило «дальше по системе только миллиметры» (ADR 0003) буквальным: `position` в буфере — это мм мира.

## Consequences

- Исходник (в единицах файла) хранится отдельно, геометрия при конвертации клонируется: смена единиц — повторная конвертация, а не перезагрузка файла.
- Иерархия glTF теряется: дерево узлов превращается в плоский список мешей. Для вьюера одной детали это приемлемо.
- Каждая повторная конвертация создаёт новые буферы. Без `dispose()` старых это утечка памяти GPU (воспроизводим на шаге 10).
