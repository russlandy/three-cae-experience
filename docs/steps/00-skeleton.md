## Как запустить

```bash
npm run dev      # dev-сервер с горячей перезагрузкой, http://localhost:5173
npm run build    # проверка типов (tsc) + production-сборка в dist/
```

Ожидаемый результат: тёмная страница, справа панель с текстом `three r186`.

## Разбор решений

### 1. Почему Vite и зачем `"type": "module"`

Vite в режиме разработки **не собирает бандл**: браузер сам грузит ES-модули (`<script type="module">`),
а Vite на лету транспилирует каждый `.ts`-файл по запросу. Поэтому старт мгновенный, а правка
файла перезагружает только его. Бандл (через Rollup/Rolldown) собирается лишь на `npm run build`.

`"type": "module"` в `package.json` говорит Node, что `.js`-файлы проекта — ES-модули (`import`),
а не CommonJS (`require`).

### 2. `build` = `tsc && vite build` — проверка типов отдельно от сборки

Vite **не проверяет типы**, он только вырезает их (так быстрее). Проверку делает `tsc` с
`"noEmit": true`: компилятор ничего не пишет на диск, только сообщает об ошибках. Если типы
не сходятся, `&&` не даст сборке продолжиться.

### 3. Важные флаги `tsconfig.json`

| Флаг | Что даёт |
|---|---|
| `"moduleResolution": "bundler"` | импорты резолвятся так, как это делает сборщик (в т.ч. `three/addons/...` через поле `exports`) |
| `"verbatimModuleSyntax": true` | импорт только типов надо писать как `import type { ... }`, иначе ошибка. Сборщик видит, какие импорты можно стереть целиком |
| `"erasableSyntaxOnly": true` | **запрещён TS-синтаксис, который нельзя просто стереть**: `enum`, `namespace`, **параметры-свойства** `constructor(private x: T)` |
| `"noUnusedLocals"` / `"noUnusedParameters"` | неиспользуемые переменные — ошибка сборки |

⚠️ **Ловушка для шага 1.** В START.md класс `Viewer` написан как
`constructor(private canvas: HTMLCanvasElement)`. С `erasableSyntaxOnly` это **не скомпилируется**.
Поле придётся объявить явно:

```ts
private canvas: HTMLCanvasElement;
constructor(canvas: HTMLCanvasElement) { this.canvas = canvas; }
```

Зачем такой флаг: TypeScript идёт к модели «типы — это аннотации, которые можно стереть»
(так Node 22+ запускает `.ts` без компиляции). `enum` и параметры-свойства генерируют JS-код,
то есть это уже не аннотации.

### 4. Размер канваса: CSS против внутреннего разрешения

У `<canvas>` два размера:

- **CSS-размер** — сколько места элемент занимает на странице (`width: 100%; height: 100%`).
- **Буфер отрисовки** — сколько реальных пикселей в нём рисуется (атрибуты `width`/`height`).

Если они не совпадают, браузер растягивает картинку, и она мылится. В нашей схеме
**размер задаёт CSS**, а рендерер на шаге 1 читает `clientWidth/clientHeight` и выставляет
буфер через `renderer.setSize(w, h, false)`. Третий аргумент `false` означает «не трогай
`style.width/height`», иначе рендерер перезапишет наш CSS фиксированными пикселями и сломает
адаптивную сетку.

`min-width: 0` у `#scene` нужен потому, что элемент grid по умолчанию не сжимается меньше
своего содержимого (`min-width: auto`). Без этого канвас с большим буфером распирает колонку
`1fr`, и при сужении окна появляется горизонтальная прокрутка.

### 5. Tree-shaking на примере

`main.ts` делает `import * as THREE from 'three'`, но production-бандл весит **0.73 КБ**.
Используется только `THREE.REVISION`, и сборщик выкинул всё остальное (`three` поставляется
как ES-модули с `"sideEffects": false`). Когда на шаге 1 появится `WebGLRenderer`, бандл
вырастет на сотни килобайт. Это наглядная иллюстрация того, что `import *` не означает «тянуть всё».
